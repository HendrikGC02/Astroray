## Features (priority order)

1. **Normalised data from the generator.** Each package node carries
   `state` ∈ {open, in-progress, blocked, paused, done, superseded, other}
   (from the fixed `status_short`; legacy tokens like "unblocked"/"stage 2 done"
   map sensibly, document the mapping), `pillar` (leading digit or ""), `track`,
   `effort`, `date` (first ISO date in Status, else ""), `prs` (PR numbers
   parsed from Status, `#NNN`), `goal` (first ≤300 chars of `## Goal`),
   `path` (repo-relative spec path). Colour comes only from `state`.
2. **Inspector panel on click**: title, state badge, full status, pillar/track/effort,
   depends-on and depended-on-by (clickable → select), owned files, linked docs,
   linked issues/PRs, GitHub links (spec blob on `main`, PR/issue URLs; repo URL
   from `git remote get-url origin`, fall back to none), and a copyable
   `python scripts/project_index.py whatis <num>` line.
3. **2D default renderer with legible labels** (`force-graph`, canvas; same
   author/API as 3d-force-graph): labels for packages drawn when zoomed in or
   selected; 3D stays available as a toggle, lazy-loading its libs only when used.
   Both libs pinned by version.
4. **Search + filters**: search box (num, title, path substring) with results
   list; `/` focuses, Enter selects the first hit, Esc clears. Per-state and
   per-pillar filters; "hide done" quick toggle.
5. **Focus mode**: selected node + 1- or 2-hop neighbourhood, or its full
   upstream/downstream dependency closure; everything else dimmed. Key `f`.
6. **Hub docs**: docs linked to > 20 packages are flagged `hub: true`; their edges are
   emitted but hidden by default behind a "Hub-doc edges" toggle. Hub docs
   still appear in the inspector's linked-docs list.
7. **Duplicate nums**: an ambiguous dependency (num maps to >1 spec) emits edges
   with `ambiguous: true` (drawn dashed/faint); no edges between members of the
   same duplicate family.
8. **Issues/PRs**: `build()` preserves `issues`; `gh-sync` also stores
   `mergedAt`/`closedAt` (PRs). Issue/PR nodes (layer off by default) link to
   packages whose num appears in their title as an exact token, and to PR
   numbers in a package's Status. Works with zero rows.
9. **Timeline layout**: alternative 2D layout with fixed positions: x = package
   `date` (undated packages in a left "undated" column), y = pillar lane with lane
   labels. Useful as the "what landed when" view.
10. **Health overlay** (toggle): ring/badge on packages that are
    (a) open/in-progress but a merged PR title references their num (stale spec;
    needs gh-sync data; e.g. pkg293 is `open` while #958 merged it),
    (b) have unresolved dependency tokens, (c) own no files. Counts shown in the panel.
11. **Freshness header**: generated-at timestamp, git HEAD short sha, gh-sync
    age (or "never"), node/edge counts. Must not embed anything per-run that
    breaks the determinism test below except the timestamp/sha line.
12. **Deep links**: URL hash `#node=<id>&focus=<0|1|2|up|down>&layout=<2d|3d|timeline>`
    restores state on load and updates on selection.
13. **Theme + responsiveness**: dark/light via `prefers-color-scheme` plus a
    toggle; `<meta name=viewport>`; panel collapsible, inspector becomes a
    bottom sheet below 700 px; resize handler.
14. **Offline fallback**: if the renderer libs fail to load, show a visible
    banner with a searchable plain-HTML table of packages (id, state, title,
    deps) built from the embedded data, so the file is still useful offline.

Out of scope: failing-gate / provisional-corpus-row overlays (no data source in
the index yet — file a follow-up if wanted), engine code, CI.
