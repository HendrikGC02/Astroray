# pkg224 — Progressive Low-Discrepancy Sampler: Research Note

Owner directive (2026-08-29): pkg131 (zero-knob adaptive sampling) is
blocked because the wavefront RNG (`WavefrontRNG`, PCG32) is white-noise —
no prefix of N samples is guaranteed well-distributed, so varying
per-pixel sample counts breaks convergence. Build the progressive sampler
first (pkg224), then pkg131 on top. Per CLAUDE.md §6, this note precedes
any implementation.

## Candidate 1 — Owen-scrambled Sobol' (hash-based, "stateless")

**Paper:** Brent Burley, "Practical Hash-based Owen Scrambling," *Journal
of Computer Graphics Techniques* 9(4), 2020.
https://jcgt.org/published/0009/04/01/paper.pdf

The paper adapts the Laine–Karras (2011) hash to approximate exact
32-level Owen scrambling of a Sobol' point with a fixed handful of
integer multiply/xor/shift ops — O(1) per draw instead of the exact
scrambler's O(32) bit-loop (each level calling a hash).

**Reference implementation (Apache-2.0):** pbrt-v4,
`src/pbrt/util/lowdiscrepancy.h` (https://github.com/mmp/pbrt-v4,
`LICENSE.txt` = Apache License 2.0 — license-compatible, matches the
license already cited in `include/astroray/sampling/wavefront_rng.h` for
the existing PCG32/MixBits port).

Two scramblers exist there. The exact one (`OwenScrambler`) walks all 32
bits, hashing a truncated prefix at each level:

```cpp
struct OwenScrambler {
    uint32_t operator()(uint32_t v) const {
        if (seed & 1) v ^= 1u << 31;
        for (int b = 1; b < 32; ++b) {
            uint32_t mask = (~0u) << (32 - b);
            if ((uint32_t)MixBits((v & mask) ^ seed) & (1u << b))
                v ^= 1u << (31 - b);
        }
        return v;
    }
};
```

The fast, Burley-2020 approximation (`FastOwenScrambler`) replaces the
32-iteration loop with a fixed sequence of reversible integer ops — this
is the one relevant to a REG-254-pinned shade kernel:

```cpp
struct FastOwenScrambler {
    uint32_t operator()(uint32_t v) const {
        v = ReverseBits32(v);
        v ^= v * 0x3d20adea;
        v += seed;
        v *= (seed >> 16) | 1;
        v ^= v * 0x05526c56;
        v ^= v * 0x53a22864;
        return ReverseBits32(v);
    }
};
```

("`v ^= v * 0x3d20adea`" — pbrt-v4, `lowdiscrepancy.h`, Apache-2.0.)

The per-draw formula is then:

```
sobol_bits   = Sobol'(sample_index, dimension)   // XOR of direction-vector
                                                  // matrix columns selected
                                                  // by set bits of sample_index
scrambled    = FastOwenScrambler(hash(pixel, dimension, seed))(sobol_bits)
u            = scrambled * 2^-32
```

**State needed:** a per-dimension Sobol' direction-vector matrix table
(`SobolMatrices32[]`, 32 × 32-bit words per dimension — pbrt-v4 ships up
to 1024 dimensions, Astroray needs far fewer since `rng_dimension` in
practice stays in the low tens per bounce). The scramble seed itself is
computed on the fly from `(pixel, dimension, scene_seed)` via a hash —
**no per-pixel scramble table is stored**, which is the property that
makes this fit the wavefront: `WavefrontRNG`'s existing
`(pixel_, sample_, dimension_, seed_)` POD state is already exactly the
input tuple this sampler needs, no new persistent state per path.

## Candidate 2 — PMJ02 (Progressive Multi-Jittered)

**Paper:** Per Christensen, Andrew Kensler, Charlie Kilpatrick,
"Progressive Multi-Jittered Sample Sequences," *Computer Graphics Forum*
37(4) (EGSR 2018), 21–33.
https://graphics.pixar.com/library/ProgressiveMultiJitteredSampling/paper.pdf

PMJ02 sequences have the progressive property (any prefix is
well-stratified) and best-in-class 2D projections (matching randomized
Sobol' (0,2) sequence error), generated by a "diagonally alternating"
strategy that fills in the next power-of-two stratification on each
doubling of N.

**Reference implementation:** the reference generator (Christensen/Pixar,
and the widely used Andrew Helmer / `pmj` open implementations) builds
the point set **once, per requested N, as a precomputed table** — the
generation algorithm is inherently sequential/incremental (each new point
depends on which strata are already occupied), not a closed-form
`f(index, dimension) -> point` you can evaluate independently per thread.
Practical GPU/wavefront use requires either (a) baking a fixed-size
table (e.g., 4096–65536 points × a few dimensions) into a `__constant__`/
global buffer ahead of time, with per-pixel decorrelation done by a
separate Cranley-Patterson rotation or shuffle seed (which then IS
per-pixel state), or (b) precomputing per-scene-seed permutation tables.
Either way it does not offer a fully stateless `sample(pixel, sample,
dimension, seed)` closed form the way hash-Owen-Sobol' does.

## Recommendation

**Hash-based Owen-scrambled Sobol' (Burley 2020 / pbrt-v4
`FastOwenScrambler`).** Reasons:

1. **Stateless, matches the wavefront's on-demand dimension model
   exactly.** `WavefrontRNG` already carries `(pixel, sample, dimension,
   seed)` as 4 POD fields and computes draws on demand per call
   (`GenerateForDimension`, `wavefront_rng.h:116`). Hash-Owen-Sobol' is a
   pure function of that same 4-tuple — it drops in as an alternate
   `GenerateForDimension`-equivalent with the identical calling
   convention, no new per-path state, no new SoA columns beyond what
   pkg92 already added.
2. **Fixed, small per-draw cost** (2 `ReverseBits32` + ~5 integer
   multiply/xor ops + a Sobol' XOR-fold over the set bits of the sample
   index — at low spp this is ≤ log2(spp) XORs, i.e. ≤ 8 for 256 spp).
   This is the right shape for the REG:254-pinned shade kernel
   (`wavefront-shade-kernels-register-saturated`): no loops over 32
   iterations, no dynamically-sized state, and the only new table
   (Sobol' direction vectors) is a `__constant__`/side-table lookup, the
   same placement pattern already proven safe for pkg186/pkg223's
   texture bindings.
3. **Already has a license-compatible, in-repo-precedented source.**
   `wavefront_rng.h` already ports PBRT-v4 (Apache-2.0) MixBits and PCG32
   patterns with the same citation style; hash-Owen-Sobol' is a drop-in
   extension of the same source and license posture.
4. PMJ02's table-generation model is a worse fit for an on-demand,
   per-thread, arbitrary-dimension wavefront sampler without adding real
   per-pixel/per-scene state (defeating the "stateless" goal), even
   though its raw 2D stratification quality is excellent.

This recommendation is research input to pkg224's spec; the spec makes
the final call along with the owner during PR review.
