Dual-lane run: god-rays, GPU render passes & settings honour

Volumetric scattering and GPU light-path AOVs land; the legacy sun renders again; Blender settings start honouring their promises.

2026-08-14 → 2026-08-15 · autonomous dual-lane run · 9 PRs merged · generated by run-report

Nine PRs merged (#615–#623), every code change dual-gated on CI and independent RTX 5070 Ti hardware verification. The engine lane shipped volumetric scattering / god-rays on both CPU and GPU and a full GPU light-path AOV pass system — both landing register-neutral via compile-time template<bool> fleet isolation, so fog-free and pass-off renders stay byte-identical to the prior fleet kernels. The integration lane built the F12 pixel-honour matrix that audits whether Blender settings actually change pixels, then acted on its findings: three honour rows now pass (world bounces, light-tree, transparent-film alpha, filter width) and a latent light-sampler crash was fixed. A separately-diagnosed correctness hole — the legacy add_sun_light rendering pure black on GPU, silently killing suns in imported .blend files — was root-caused and fixed (0.0 → 0.633 vs 0.637 analytic). Parked honestly with filed follow-ups: one filter row (0.83%, sub-threshold → pkg203), the register-hostile honour items (pkg201 Stage 3), and transparent-glass compositing. Two agents were killed mid-flight by session limits and recovered without loss; every GPU-lock handoff was clean.

Play with it: the all-features addon was rebuilt (CUDA, OpenMP-off), passed the headless smoke gate, and is installed into Blender 5.1 now. Distributable: dist/astroray-4.0.0-cuda.zip.
