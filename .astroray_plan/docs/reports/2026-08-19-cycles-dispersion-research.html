01Executive summary

Cycles got real chromatic dispersion on 2026-08-18, merged as PR #162041 by Weizhen Huang (co-authored with Sebastian Herholz). It ships in Blender 5.3 alpha — not in the 5.1/5.2 builds you run. The feature is small (~500 lines of kernel code), is not a full spectral rewrite, and is a faithful port of the OpenPBR Surface v1.1.1 dispersion model.

What Cycles does

  • Two artist knobs on Principled BSDF → Transmission: Dispersion Scale (0–1) and Abbe Number (9–91, default 20).
  • Derives a two-term Cauchy n(λ) = A + B/λ² from the Abbe number.
  • Stays RGB: samples one "hero" wavelength per path, evaluates Cauchy at it, then folds back to RGB via a D65-weighted CIE look-up with a 1/pdf correction.
  • Compiles on every backend (CPU SVM+OSL, CUDA, OptiX, Metal, HIP, oneAPI).

What Astroray already has

  • A true spectral renderer: 4 hero wavelengths (360–830 nm), Jakob–Hanika RGB→spectrum upsampling, CIE 1964 10° observer.
  • Sellmeier dispersion (Schott presets: BK7, SF11, fused silica, diamond) — more physical than Cauchy.
  • A Cauchy Principled path (pkg187) that is a verbatim port of this exact Cycles PR — bit-for-bit parity target.
  • Hero-wavelength collapse (terminateSecondary()) + spectral MIS for caustics (SMS, Hanika 2015 §4).
Headline finding

Astroray is already ahead of Cycles on the physics. Its Cauchy path is the same model Cycles just merged, but rendered spectrally rather than RGB-with-one-wavelength. The valuable, unexplored learnings are not the dispersion model — they are Cycles' wavelength importance sampling, its artist-interface decisions, and a handful of research techniques Astroray hasn't touched (spectral ray differentials, per-bounce spectral MIS). Two concrete, actionable discrepancies with the merged build were also found — see §6.

Where it is not

Dispersion is only on the Principled BSDF Transmission panel. The legacy Glass BSDF did not gain it, and coat is explicitly excluded. EEVEE/Storm expose the two sockets for node-tree compatibility but mark them "Not used by EEVEE" — dispersion is Cycles-only.

03The physics model: Cauchy from Abbe

Cycles did not choose Sellmeier or a measured spectrum. It implemented OpenPBR v1.1.1 verbatim, which uses the two-term Cauchy formula because it is the minimal closed form fully determined by two artist parameters (IOR + Abbe number). The IOR at any wavelength is:

// OpenPBR Surface v1.1.1 Eq. (55)
n(λ) = A + B / λ²            (λ in μm)

The two Cauchy coefficients are solved from the IOR at the Fraunhofer d line (587.6 nm) and the Abbe V-number, using the C (656.3 nm) and F (486.1 nm) lines:

// OpenPBR Surface v1.1.1 Eq. (56)
B = (nd − 1) / (Vd · (λF−2 − λC−2))
A = nd − B/λd²
Vd = abbe_number / dispersion_scale        // scale=0 ⇒ no dispersion

The exact kernel code (this is the whole trick):

// intern/cycles/kernel/closure/bsdf_microfacet.h — bsdf_glass_ior()
const float lambda_d = 0.5876f, lambda_C = 0.6563f, lambda_F = 0.4861f;
const float fac = 1.0f / (1.0f/(lambda_F*lambda_F) - 1.0f/(lambda_C*lambda_C));
const float inv_lambda_d_sq = 1.0f / (lambda_d * lambda_d);
const float B = (ior - 1.0f) * inv_abbe * fac;      // Eq. 56
const float A = ior - B * inv_lambda_d_sq;
const float wavelength = sample_wavelength(sd->rand_wavelength);
ior = A + B / sqr(wavelength);                          // Eq. 55
Astroray parity

This is character-for-character what Astroray already implements in plugins/materials/principled.cpp:229-238 (cauchyAB()) and include/astroray/gpu_dispersion.cuh:36-39 (gpu_cauchy_ior()), with identical Fraunhofer constants and the same inv_abbe = dispersion_scale / abbe_number mapping. The Cauchy model itself is not news to Astroray. Astroray additionally has the more physical Sellmeier model (plugins/materials/dielectric.cpp:9-14) with Schott presets — something Cycles does not expose.

Why Abbe number as the artist control

OpenPBR's rationale (quoted from the spec) is the single best interface decision in this work:

"The Abbe number itself is not very intuitive to work with, as the dispersion effect increases as the Abbe number decreases … We therefore prefer a more artist-friendly parametrization, where the Abbe number is specified by Vd = transmission_dispersion_abbe_number / transmission_dispersion_scale … the transmission_dispersion_scale therefore functions as a convenient roughly linear slider from low to high dispersion."

Real-material reference values (from the spec): glass Abbe 20–91 (Schott), water and diamond 55–56, rutile (TiO₂) 9.87 — the UI's 9–91 range brackets exactly this. Note the counter-intuitive inverse: a low Abbe number means stronger dispersion.

04How Cycles renders it (RGB + hero wavelength)

The key architectural decision: Cycles does not become a spectral renderer. The Spectrum type stays a 3-channel RGB triple. Instead it adopts hero-wavelength sampling — the classic idea from Wilkie et al. 2014 — but (interestingly) credits it to OpenPBR + a 2023 "Metameric" paper rather than to Wilkie.

Wavelength sampling — the subtle part

The hero wavelength is drawn once per path from a luminance-weighted D65 distribution, fitted to a sigmoid CDF (script cie_d65_luminance_fit.py). The author's noise analysis is directly relevant to Astroray:

  • Pure luminance sampling → smooth body but green noise in caustics (human eye is green-sensitive).
  • Uniform sampling → noisier overall.
  • Her solution: add a constant to the CIE luminance CMF before fitting ("we want a bit of all the wavelengths"), landing between the two extremes.
// intern/cycles/kernel/util/colorspace.h — sample_wavelength()
rand = N * rand + y0;
prob = a * rand * (1.0f - rand);            // sigmoid derivative = PDF
prob *= (WAVELENGTH_CIE_MAX - WAVELENGTH_CIE_MIN) / N;
wavelength = -fast_logf(1.0f/rand - 1.0f) / a + x0;   // inverse sigmoid
return clamp(wavelength, 0.38f, 0.78f);      // μm

λ → RGB (the "uplifting")

The wavelength is converted back to RGB using CIE 1931 2° colour-matching functions × D65 SPD, cited to "Metameric: Spectral Uplifting via Controllable Color Constraints" (van de Ruit & Eisemann) Eq. (1). This is the exact spot where a spectral renderer like Astroray differs: it never needs this lift, because it carries the spectrum (and the source SPD) all the way to the observer. That matters — see the chromatic-light-source limitation below.

Acknowledged limitation (from the PR thread)

With a spectrally-narrow light (e.g. a Rec.2020 red light), a physically-correct prism shows only the red slice of the rainbow — but Cycles "solves for the full D65 SPD" and then tints the whole dispersed rainbow red. The author's reply: "It's not physically correct, because we don't know the spectrum of the light source … in the future if we switch to spectral, then uplifting would naturally be added." Astroray already knows the source SPD and is immune to this — a concrete differentiator worth asserting in a test (see §6).

06What's genuinely new & not yet explored in Astroray

This is the section you asked to be highlighted. Two findings are actionable discrepancies with the merged build; the rest are research techniques that Astroray's many research runs have not yet surfaced.

6.1 — The addon's forward-compat probe will NOT round-trip in Blender 5.3

Actionable discrepancy #1

blender_addon/__init__.py:3454-3455 probes for sockets named 'Dispersion Scale' and 'Dispersion Abbe Number'. But the merged Blender sockets are named 'Transmission Dispersion Scale' and 'Transmission Dispersion Abbe Number' (source: node_shader_bsdf_principled.cc, .add_input<decl::Float>("Transmission Dispersion Scale"_ustr)). put_float does an exact node.inputs.get(name) match, so the probe will still return None even on a 5.3 build. The comment's promise — "start round-tripping automatically the day that PR ships" — won't hold until the probe names are updated.

6.2 — pkg187's reference is no longer "WIP"; parity target moved

Actionable discrepancy #2

Astroray's Cauchy port (pkg187) and its docs pin PR #162041 as an unmerged WIP (pkg187-principled-dispersion-research.md, and the gpu_dispersion.cuh:29-33 comment "Cycles' WIP Principled dispersion"). It merged 2026-08-18. The merged code is what was fetched here (bsdf_glass_ior in bsdf_microfacet.h) and it matches Astroray's port — but the "WIP"/"unmerged" wording across the repo is now stale, and the parity target should be re-verified against the merged commit rather than the PR head.

6.3 — Wavelength importance sampling (the biggest variance win)

Astroray draws the hero wavelength uniformly (src/spectrum.cpp:82-100, sampleUniform()). Cycles' D65-luminance-weighted sigmoid CDF is a strictly-better proposal for the dispersive-caustic case where Astroray's hue_spread/bright_coverage gates already fight chromatic noise. Adopting a luminance-weighted hero-λ draw (with the "constant + curve-fit" trick) is a small, self-contained change with a measurable convergence payoff in the prism-rainbow tests.

6.4 — Spectral ray differentials

Elek et al. 2014 (DOI 10.1111/cgf.12418) tracks dλ along rays so dispersion can be filtered instead of point-sampled — and enables "dispersion-only-in-caustics" sampling (concentrate wavelength samples where |∂θ/∂λ| is large). Not present in Astroray's research corpus; directly applicable to its ray structure and its caustic path.

6.5 — Per-bounce spectral MIS (vs per-path hero)

Petitjean & Bauszat 2018 (DOI 10.1111/cgf.13474, spectral gradient sampling) and Pediredla et al. 2020 (DOI 10.1145/3414685.3417793) re-sample λ per dispersive bounce with spectral MIS weighting, rather than collapsing to one hero per path. This attacks the exact firefly pattern that hero-wavelength suffers in dispersive caustics — a natural extension of Astroray's existing SMS spectral-MIS work.

6.6 — Dispersion on specular reflection

PBRT v4 documents it as a known gap; Cycles also only disperses transmission. Astroray's terminateSecondary() also fires only on refraction. Keeping all 4 companion wavelengths for the reflected lobe (dispersion there is second-order but present at grazing angles) would be strictly more correct and is currently unclaimed.

6.7 — Minor citation typo (repo hygiene)

include/astroray/manifold/half_vector_constraint.h:11 lists the MNEE 2015 authors as "Hanika, Droske, Manakov" — the published paper is "Hanika, Droske, Fascione" (DOI 10.1111/cgf.12681). One comment elsewhere in the repo (sms_attempt.h) already has it right.

6.8 — The frontier: Gaussian / wave-optics dispersion

Steinberg & Pharr 2025 (DOI 10.1111/cgf.70322) replaces discrete wavelengths with Gaussian (Wigner) space-frequency distributions, making dispersion analytic rather than Monte-Carlo. High-risk, high-reward — but worth tracking as Astroray pushes spectral caustics.

07Other renderers: a survey

Across the ecosystem, almost everyone uses the same recipe — Cauchy n(λ) + one hero wavelength per path folded back to RGB. The genuinely spectral renderers are the exception, and none of the open-source spectral renderers does dispersive dielectric IOR well — that niche is Astroray's.

08Ranked recommendations

1Fix the addon probe names to Transmission Dispersion Scale / Transmission Dispersion Abbe Number (with the short forms as fallbacks), so dispersion round-trips on 5.3.

2Re-verify the pkg187 Cauchy parity against the merged commit (f15daf81bf7c…) and refresh the stale "WIP/unmerged" comments and docs.

3Adopt luminance-weighted hero-λ sampling (D65 CDF + constant fit) to cut chromatic noise in dispersive caustics — the one concrete convergence win Cycles found.

4Add a chromatic-light-source dispersion test (line emitter through a prism) as a differentiating oracle: Cycles fails it by design, Astroray should pass — a strong parity/superiority signal.

5Prototype spectral ray differentials (Elek 2014) and/or per-bounce spectral MIS (Petitjean 2018) for dispersion — the two research gaps most aligned with Astroray's caustic work.

6Keep the companion wavelengths on specular reflection, terminating only on actual refraction — a correctness improvement over both PBRT and Cycles.

7Track OpenPBR's dispersion section as it evolves; Astroray already conforms via pkg187, and OpenPBR is becoming the cross-vendor interface for dispersion.
